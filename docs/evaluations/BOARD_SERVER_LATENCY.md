# 실제 Android 기기의 게시판 서버 조회 시간

이 문서는 운영 게시글 4개로 진행한 현재 버전 단독 측정입니다. 이후 별도 합성 게시글로 수행한 [1,000개 전후 비교](BOARD_SERVER_COMPARISON.md)와 [20·100·500개 추가 비교](BOARD_SERVER_SCALE_COMPARISON.md)를 따로 기록했습니다. 아래 수치와 후속 비교의 수치는 서로 다른 데이터 조건입니다.

2026-10-14에 USB로 연결한 Android 휴대폰에서 서버 연결 profile 빌드를 실행하고, 실제 로그인 세션으로 게시판 첫 페이지를 반복 조회했습니다. 합성 데이터나 Firestore Emulator를 사용한 결과와 구분합니다.

<br><br><br>





## 측정 환경

| 항목 | 조건 |
|---|---|
| 기기 | Samsung SM-S931N, Android 16 / API 36 |
| 앱 | Flutter profile, Android arm64, `1.0.0+6` |
| 연결 모드 | `DEMO_MODE=false`, 실제 Firebase Authentication 세션 |
| 쿼리 | 활성 게시글, 생성 시각과 문서 ID 정렬, 첫 페이지 최대 20개 |
| 조회 소스 | `GetOptions(source: Source.server)` |
| 반환 문서 | 34회 모두 4개, 캐시 응답 0회 |
| 반복 조건 | 첫 조회 1회, 예열 3회, 측정 30회. 조회 후 Flutter 프레임 완료 시점에서 1초 간격 |
| 서버 변경 | 측정에서 게시글 생성·수정·삭제나 규칙 배포를 하지 않음 |

기존 휴대폰 APK를 로컬에 보관하고 서명이 같은 것을 확인한 뒤 `adb install -r`로 업데이트했습니다. 앱 데이터 삭제 없이 로그인 세션이 유지되는 것을 확인했습니다. 기기의 네트워크 대역폭이나 다른 앱의 실행 상태는 통제하지 않았습니다.

<br><br><br>





## 측정 결과

| 항목 | 첫 조회 1회 | 예열 후 30회 중앙값 | 예열 후 30회 p95 |
|---|---:|---:|---:|
| 서버 조회 요청부터 SDK 결과 수신까지 | 2,412.793ms | 524.526ms | 547.677ms |
| 목록 조회 시작부터 Flutter 프레임 완료 콜백까지 | 2,420.483ms | 531.306ms | 559.274ms |

예열 후 SDK 조회 응답은 최소 422.164ms, 최대 602.893ms였습니다. 결과를 모델로 변환하는 시간의 중앙값은 0.068ms, 목록 로딩 완료부터 Flutter 프레임 콜백까지의 중앙값은 9.512ms였습니다. 서로 다른 지표의 중앙값을 더하거나 빼서 다른 중앙값으로 해석하지 않습니다.

30개 값을 정렬해 중앙값을 계산했고, p95는 `ceil(30 × 0.95)`번째 값으로 계산했습니다. 첫 조회와 다음 3회의 예열은 반복 측정 통계에서 제외했습니다. 첫 조회가 반복 조회보다 느렸지만, 연결·인증·SDK 준비 중 어느 요인이 차이를 만들었는지 별도로 분리해 측정하지 않았습니다.

<br><br><br>





## 수치의 의미와 한계

- SDK 조회 시간은 휴대폰에서 본 요청 완료 시간으로, 네트워크와 SDK 처리를 포함합니다. 서버 내부 실행 시간만 측정한 값은 아닙니다.
- Flutter 프레임 시간은 `addPostFrameCallback`에서 측정했습니다. GPU 래스터 완료나 실제 디스플레이에 픽셀이 나타난 시점까지 측정하지 않았습니다.
- 이번 서버 쿼리가 반환한 문서는 4개입니다. 게시글 1,000개를 구성한 로컬 초기 조회량 비교 결과와 데이터 조건이 다릅니다.
- 동일 기기·한 세션의 30회 반복 결과입니다. 다른 기기·네트워크나 전체 사용자의 응답 시간을 대표하지 않습니다.
- 이 단독 측정에서는 구버전의 실서버 응답 시간을 측정하지 않아 **전후 속도 개선율을 산출하지 않았습니다.** 운영 규칙은 조회 한도를 요구하여 기존 무제한 목록 쿼리를 허용하지 않습니다. 후속 비교는 별도 테스트 경로에서 제한된 임시 읽기 권한으로 수행했습니다.
- 시간·문서 수·캐시 여부만 기록했습니다. 게시글 내용, 계정 식별자, 이메일, 인증 토큰은 결과 파일에 포함하지 않았습니다.

## 코드와 재현

측정 로그는 `BOARD_LATENCY_PROBE=true`로 빌드했을 때만 활성화됩니다. 일반 빌드에서는 자동 반복 조회와 측정 로그가 꺼집니다. 측정 빌드에서 게시판을 한 번 열고 완료될 때까지 다른 화면 이동이나 추가 새로고침을 하지 않습니다.

```powershell
flutter build apk --profile --target-platform android-arm64 --dart-define=DEMO_MODE=false --dart-define=BOARD_LATENCY_PROBE=true --build-number=6 --no-pub
```

조회 로그 34개와 프레임 로그 34개를 모아 다음 스크립트로 계산합니다. 캐시 응답, 누락·중복 ID, 조회 오류, 쿼리와 화면의 문서 수 불일치가 있으면 집계를 중단합니다.

```powershell
./tools/summarize_board_latency.ps1 -InputPath <측정-로그-경로> -OutputPath <결과-JSON-경로>
```

- [측정 요약과 APK SHA-256](board-server-latency-2026-10-14.json)
- [개인정보 없는 측정 이벤트 68개](board-server-latency-events-2026-10-14.json)
- [측정 스위치와 로그](../../lib/services/board_latency_probe.dart)
- [조회 시간과 모델 변환 시간](../../lib/services/post_service.dart)
- [목록 로딩과 첫 프레임 시간](../../lib/widgets/board/board_paged_list.dart)
- [중앙값·p95 집계 스크립트](../../tools/summarize_board_latency.ps1)

측정용 코드의 정적 분석에 오류가 없었고, 기존 게시판 위젯·페이지 조회 테스트 10개가 통과했습니다. 집계 스크립트의 중앙값과 p95 계산은 값이 알려진 별도 입력으로 확인했습니다.

측정 후 휴대폰에는 `BOARD_LATENCY_PROBE`를 지정하지 않은 동일 버전의 profile 빌드를 다시 설치했습니다. 로그인과 정상 게시판 표시가 유지되고 측정 로그가 발생하지 않는 것을 확인했습니다. 휴대폰에 자동 반복 조회가 켜진 빌드는 남기지 않았습니다.
