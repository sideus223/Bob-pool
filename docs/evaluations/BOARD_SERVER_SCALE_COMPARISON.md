# 게시글 수에 따른 실서버 조회 비교

합성 게시글 **20개·100개·500개** 조건에서 기존 전체 구독과 현재 최대 20개 조회를 예열 후 20쌍씩 비교했습니다. 게시글 수와 반복 측정 횟수는 서로 다른 값입니다.

<br><br><br>





## 게시글 수별 결과

아래 시간은 **첫 서버 응답을 SDK가 반환할 때까지의 중앙값**입니다. 네트워크와 SDK 처리를 포함합니다. 감소율이 음수이면 현재 방식이 더 오래 걸렸다는 뜻입니다.

| 게시글 수 | 기존 반환 | 현재 반환 | 기존 중앙값 | 현재 중앙값 | 응답 시간 감소율 |
|---|---:|---:|---:|---:|---:|
| 20 | 20개 | 20개 | 527.939ms | 529.021ms | -0.2% |
| 100 | 100개 | 20개 | 1,265.898ms | 486.253ms | 61.6% |
| 500 | 500개 | 20개 | 4,880.662ms | 461.766ms | 90.5% |

20개에서는 **527.939ms → 529.021ms**, 약 1.1ms 차이로 현재 방식의 시간 이득이 나타나지 않았습니다. 100개에서는 **1,265.898ms → 486.253ms**로 약 61.6%, 500개에서는 **4,880.662ms → 461.766ms**로 약 90.5% 감소했습니다.

각 행의 감소율은 **그 행에서 함께 측정한 기존·현재 중앙값**으로 계산했습니다. 서로 다른 데이터 수의 시간을 나누거나, 데이터 증가에 따른 선형 관계를 추정하지 않았습니다.

| 게시글 수 | 기존 p95 | 현재 p95 | 현재 방식이 빨랐던 쌍 |
|---|---:|---:|---:|
| 20 | 600.060ms | 599.299ms | 9/20 |
| 100 | 1,449.235ms | 531.894ms | 20/20 |
| 500 | 5,213.860ms | 518.715ms | 20/20 |

전체 144회에서 캐시 응답과 오류는 0회였습니다. 각 조건의 앞 4쌍·8회는 예열로 보관하고, 뒤 20쌍·40회만 통계에 사용했습니다. p95는 방식별 20개 값을 정렬한 `ceil(20 × 0.95)`번째 값입니다.
