# アカウント別のサーバー保存

サーバー接続モード（`DEMO_MODE=false`）は好み・推薦・選択履歴をFirestoreに保存します。デモはログインやサーバー接続を使わずSharedPreferencesに保存します。推薦計算、Softmax抽選、学習はどちらもアプリ内で実行します。Firebaseや別の学習サーバーがモデルを学習する構成ではありません。

<br><br><br>





## 保存先と形式

`users/{Firebase UID}/preferences/current`

```text
schemaVersion: 1
values:
  favorites: [メニューID]
  added_<気分> / removed_<気分> / disliked_<気分>: [メニューID]
  selections: 旧アカウント別の選択回数（移行用）
  interaction_history:
    <メニューID>:
      recommendationCount / selectionCount: 累計回数
      lastRecommendedAt / lastSelectedAt: UTC epoch milliseconds または null
  learning: バージョン・重み・標本数・最近の推薦と反応
updatedAt: Firestoreサーバー時刻
```

本人だけが自分の`current`文書を読み書きできます。別アカウント、未ログイン、別パス、許可していない最上位フィールド・好み項目はルールで拒否します。リストの型・重複・長さ、履歴mapのサイズを確認し、map内部の各値はアプリで解析・検査します。ユーザーが変更できる記録なので、サーバーが検証した食事実績や学習正解とは扱いません。

<br><br><br>





## 同時変更と接続失敗

- 変更ごとに最新文書を読むFirestoreトランザクションを使い、2台の選択回数・お気に入り変更が上書きし合うことを防ぎます。
- コールバックは独立したコピーだけを変更し、再実行によるアプリ状態の重複変更を防ぎます。
- 要求開始時のアカウントを固定し、途中で変わった場合は処理を拒否します。
- 読み取りは`Source.server`を使います。接続失敗を端末記録で置き換えたり、保存失敗を成功として表示したりしません。
- 読み取り・トランザクションのタイムアウトは15秒、書き込みトランザクションの試行は最大3回です。失敗時は既存のエラー領域で再試行を案内します。
- インターネット接続が必要です。オフライン書き込みキューと自動再送は実装していません。

トランザクションとオフライン時の動作は[Firebase公式資料](https://firebase.google.com/docs/firestore/manage-data/transactions)に基づきます。

<br><br><br>





## 旧端末記録の移行

サーバー文書がない場合だけ、同じUIDの`bap_pool_v2_<UID>_`記録から作成します。トランザクション内でも存在を確認し、別端末が先に作った文書を上書きしません。文書が存在する場合はサーバーを基準とし、古い端末記録を自動マージしません。端末記録はバックアップとして保持します。デモと所有者不明の旧共通キーは移行しません。

気分・お気に入りの初期化は項目を空にするだけで文書を削除しません。古い記録の再移行を防ぐため、クライアントによる文書削除も拒否します。

## 検証と学習モデル

`test/firestore_preference_store_test.dart`の9テストはFakeFirestoreで初回移行、新端末の再取得、アカウント分離・途中変更、書き込み直列化、障害復旧、ローカル代替の禁止、未知スキーマの保持を確認します。Firestore Emulatorではアクセス制御と2クライアントの同時トランザクションを確認します。これらは実アカウントや実際の2端末での検証とは区別します。

推薦条件・候補・抽選確率・反応を最近30日以内、最大64件の表示記録に関連付け、反応のある記録を優先します。モデルと好みの変更を同じトランザクションで保存します。[学習・保存方針](LEARNING_MODEL.md)

現在は`version=2`、重み146個です。バージョン1の反応をメニューと当時の条件から再構成し、次の通常書き込みで同じトランザクション内で変換します。Android SDKで実サーバー保存、新セッションの再取得、モデルの互換動作を確認しました。[接続検証](APK.md)
