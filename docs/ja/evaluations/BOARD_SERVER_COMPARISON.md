# Android実機での掲示板取得方式の比較

合成投稿1,000件で実施した最初の比較です。少量のデータも含む後続測定は[投稿数ごとの比較](BOARD_SERVER_SCALE_COMPARISON.md)にまとめています。

2026-10-14に同じ端末と実Firestoreで1,000件を取得しました。全件購読の最初のサーバー応答と20件のページ取得を比較し、**応答時間の中央値は9,734.206msから484.740msへ95.020%減少**しました。旧版の取得コードを同じSDKで再現した結果であり、旧APK全体と現在のアプリ全体の比較ではありません。

<br><br><br>





## 条件

| 項目 | 条件 |
|---|---|
| 端末 | Samsung SM-S931N、Android 16 / API 36、USB接続 |
| アプリ | 同じFlutter profile APK、Android arm64、`1.0.0+7` |
| サーバー | 実Firestoreの既定データベース、`asia-northeast3`（ソウル） |
| 認証 | 同じFirebase Authenticationセッション |
| データ | 運用投稿と分離した合成投稿1,000件、すべて`deleted=false` |
| 本文 | 文書ごとに異なる決定的なASCII文字列1,024文字、固有の作成時刻 |
| 以前 | `4848f33`直前の`createdAt`降順の全件購読、最初の非キャッシュ応答 |
| 現在 | `deleted=false`、`createdAt`降順・文書ID整列、`limit(20)`、`Source.server` |
| 反復 | 24組・48回。最初の4組をウォームアップとして除き、各方式20回を集計 |
| 順序 | 奇数組は以前→現在、偶数組は現在→以前。取得後1秒間隔 |
| キャッシュ | ディスク永続化を無効化、全48回が非キャッシュ。SDKメモリ最適化は別途統制せず |
| エラー | 0回。以前は毎回1,000件、現在は毎回20件 |

運用ルールは無制限クエリを拒否するため、承認済みの別テストパスだけに、ログイン済み所有者が1時間読み取れるルールを適用しました。クライアント書き込みは禁止しました。運用投稿のコピー・変更はありません。

<br><br><br>





## 結果

端末でクエリを開始してからSDKが結果を返すまでを測定しました。ネットワーク・SDK処理・最初のスナップショット受信を含み、サーバー内部処理だけの時間ではありません。

| 指標 | 全件購読 | 現在の初回ページ取得 |
|---|---:|---:|
| 初回返却文書数 | 1,000件 | 20件 |
| 応答中央値 | 9,734.206ms | 484.740ms |
| 応答p95 | 10,821.628ms | 527.585ms |
| 応答平均 | 9,867.802ms | 488.781ms |
| 応答最小 | 9,170.142ms | 465.064ms |
| 応答最大 | 11,246.909ms | 528.051ms |
| 応答後のモデル変換中央値 | 1.802ms | 0.096ms |

- 返却文書数の減少率：`(1,000 - 20) / 1,000 × 100 = 98%`
- 応答中央値の減少率：`(9,734.206 - 484.740) / 9,734.206 × 100 = 95.020%`
- ウォームアップを除く**全20組で現在の方式が速い結果**でした。

中央値は整列した20値の中央2値の平均、p95は`ceil(20 × 0.95)`番目の値です。順序、ウォームアップ区分、文書数、非キャッシュ、完了状態がすべて正しい場合だけ統計を生成しました。異なる指標の中央値を足して合計時間とは解釈しません。

<br><br><br>





## 解釈の範囲

「実機・実サーバーで合成投稿1,000件を比較し、初回取得応答の中央値を約95.0%減らした」と説明できます。

1端末・1セッションで測定し、ネットワーク帯域やほかのアプリを統制していません。以前の運用投稿4件の単独測定（中央値524.526ms）とはデータとセッションが異なるため、[単独測定](BOARD_SERVER_LATENCY.md)の値と割り算して改善率を出しません。

以前の購読は最初の応答後に終了しました。継続的な更新、カードのコメント数購読、全画面描画、全ページの取得、課金額は比較していません。現在はまず20件だけ取得するため、1,000件すべてを取得した状態とは提供範囲が異なります。**アプリ全体が95%速くなったという意味ではありません。**

<br><br><br>

再測定には管理者権限で合成データと限定した読み取り権限を準備します。有効期限・所有者制限の許可／拒否9条件をローカルEmulatorで通過してからサーバーに適用しました。

```powershell
flutter build apk --profile --target-platform android-arm64 --target=tools/board_query_comparison_main.dart --dart-define=DEMO_MODE=false --dart-define=BOARD_COMPARE_RUN_ID=<test-id> --build-number=7 --no-pub
./tools/summarize_board_comparison.ps1 -InputPath <log-path> -OutputPath <statistics-json-path>
```

測定APKは当時保存した一時エントリーポイントでビルドしました。現在のコードは投稿数選択を追加した版で、既定値は1,000件です。本文は文書`i`と`segment=0..15`について`SHA256("board-fixture-v1:{i}:{segment}")`の64文字hexを連結しました。タイトル・フィールド・時刻を含むfixtureとAPKのハッシュはJSONに保存しました。集計計算は既知の50%減少入力で確認しました。

<br><br><br>





## 測定後の整理

合成文書1,000件を削除し、残り0件を確認しました。元のルールリリースを復元し、ソースSHA-256が事前バックアップと一致することも確認しました。

通常の`lib/main.dart`のprofile版`1.0.0+7`を同じ署名で上書きしました。データを消さずログインと正常画面を維持し、新プロセスで測定ログが出ないことを確認しました。公開資料には本文、アカウント識別子、メール、認証トークンを含めていません。
