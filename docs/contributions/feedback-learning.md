# 피드백 학습

<br><br><br>





## 학습 구조

![음식 특징과 사용자 반응을 학습해 다음 추천 점수에 반영하는 과정](../images/learning-model.png)

좋아요·메뉴 선택·별로예요 반응을 음식의 주재료·조리법·형태·맛과 연결해 학습합니다. 학습한 특징을 다음 추천 점수에 반영해, 아직 반응을 남기지 않은 메뉴도 개인 취향에 맞춰 평가합니다.

<br><br><br>





## 기존 방식의 문제

원본은 좋아요를 찜 목록에 저장하고, 별로예요를 남긴 메뉴는 추천에서 제외했습니다. 기분별로 메뉴를 직접 추가하거나 제거할 수도 있었지만, 음식의 공통 특징을 이용한 취향 학습은 없었습니다.

| 한계 | 원인 |
|---|---|
| 좋아요가 다음 추천에 반영되지 않음 | 찜 목록은 저장하지만 원본의 추천 후보 계산에는 사용하지 않음 |
| 선호를 다른 메뉴로 확장하기 어려움 | 메뉴별 제외와 수동 태그 설정만으로는 재료·조리법 같은 공통 특징에 대한 취향을 반영하기 어려움 |

<br><br><br>





## 해결 과정

좋아하는 메뉴를 기록하는 것에서 더 나아가, **어떤 특징의 음식을 좋아하는지 학습하고 다른 메뉴에도 반영하는 구조**를 구상했습니다.

### 1. 메뉴를 음식 특징으로 표현

메뉴 이름 대신 주재료·조리법·음식 형태·맛을 학습 입력으로 사용했습니다. 기분과 식사 상황도 함께 반영해 같은 음식이라도 상황에 따라 선호가 달라질 수 있도록 했습니다.

예를 들어 제육볶음과 닭갈비에 긍정 반응을 남겼다면, 두 음식의 공통된 볶음 특징을 다른 볶음 메뉴의 점수에도 반영할 수 있습니다.

### 2. 사용자의 반응을 학습 기준으로 연결

| 반응 | 처리 |
|---|---|
| 좋아요·메뉴 선택 | 긍정 반응으로 학습 |
| 별로예요 | 부정 반응으로 학습 |
| 반응 없음·다른 메뉴 보기·레시피 열람 | 학습에서 제외 |

같은 추천에서 좋아요와 메뉴 선택을 모두 눌러도 표본 하나로 처리했습니다. 반응이 없다는 이유만으로 싫어하는 음식이라고 판단하지 않도록 했습니다.

### 3. 음식 특징과 반응의 관계를 학습

개인별 로지스틱 회귀 모델로 음식 특징과 긍정·부정 반응의 관계를 학습하고, 그 결과를 기존 추천 점수에 더하거나 빼도록 했습니다. 좋아요를 취소하거나 반응을 바꾸면 남아 있는 기록으로 다시 학습해 변경된 취향을 반영했습니다.

### 4. 기록이 쌓일수록 학습의 영향을 확대

반응 4개·서로 다른 메뉴 2개부터 작은 보정을 적용했습니다. 반응 8개·메뉴 3개 이상이고 긍정과 부정 반응이 모두 있으면 보정 폭을 키웠습니다. 처음에는 기본 태그로 추천하고, 충분한 반응이 쌓이면 개인 취향의 비중을 높였습니다.

학습으로 점수가 높아져도 예산·맵기·직접 제외한 메뉴의 조건은 그대로 지키도록 했습니다.

<br><br><br>





## 결과

좋아요와 불호를 메뉴별 기록으로만 남기지 않고, 음식 특징에 대한 취향으로 다음 추천에 반영했습니다. 학습에 사용하지 않은 메뉴에서도 선호 특징이 추천 점수에 반영되는지 확인했습니다.

### 비교 테스트

같은 추천 로직에서 학습을 적용하기 전후를 비교했습니다. 가상 취향 5종으로 학습하고, 반응을 학습에 사용하지 않은 별도의 메뉴로 평가했습니다.

| 지표 | 학습 적용 전 | 학습 적용 후 | 변화 |
|---|---:|---:|---:|
| 가상 취향 5종의 선호 음식 추첨 확률 | 평균 42.30% | 평균 74.78% | **32.48%p 상승** |

각 수치는 가상 취향에 맞는 음식에 배정된 추첨 확률입니다. 실제 사용자 만족도나 추천 정확도를 측정한 값은 아닙니다.
