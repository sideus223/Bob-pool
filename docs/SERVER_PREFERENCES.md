# 계정별 서버 저장

Firebase 연결 모드(`DEMO_MODE=false`)는 취향과 추천·선택 이력을 Firestore에 저장한다.
데모 모드는 계정과 서버 연결 없이 기존 SharedPreferences를 사용한다.
추천 계산·Softmax 추첨·피드백 학습은 앱에서 실행한다. 연결 모드는 계정별 모델과 추천 기록도 서버에 저장한다.
Firebase가 학습을 실행하거나 별도 학습 서버가 주기적으로 실행되는 구조는 아니다.

<br><br><br>





## 저장 위치와 형식

`users/{Firebase UID}/preferences/current`

```text
schemaVersion: 1
values:
  favorites: [메뉴 ID]
  added_<기분> / removed_<기분> / disliked_<기분>: [메뉴 ID]
  selections: 기존 계정별 선택 횟수 (이관용)
  interaction_history:
    <메뉴 ID>:
      recommendationCount / selectionCount: 누적 횟수
      lastRecommendedAt / lastSelectedAt: UTC epoch milliseconds 또는 null
  learning: 버전·가중치·표본 수·최근 추천 및 반응 (LEARNING_MODEL.md 참조)
updatedAt: Firestore 서버 시각
```

각 계정은 자신의 `current` 문서만 읽고 쓸 수 있다. 다른 계정·비로그인 사용자의 접근,
다른 문서 경로, 허용되지 않은 최상위 필드·취향 항목을 규칙에서 차단한다.
리스트의 타입·중복·길이와 이력 맵의 크기를 검사한다. 이력 맵 내부의 개별 값은 앱에서 해석·검사한다.
사용자가 수정 가능한 취향 기록이므로 서버가 검증한 식사 실적이나 학습 정답으로 간주하면 안 된다.

<br><br><br>





## 동시 변경과 연결 실패

- 각 변경은 서버의 최신 문서를 읽는 Firestore 트랜잭션으로 처리한다. 기기 두 대의 선택 횟수와 찜 변경을 서로 덮어쓰지 않는다.
- 트랜잭션 콜백은 분리된 데이터 사본만 변경하므로 재실행 때 앱 상태를 중복 변경하지 않는다.
- 요청 시작 시 계정을 캡처한다. 계정이 바뀌면 작업을 거부하며 새 계정의 문서로 전환하지 않는다.
- 읽기는 `Source.server`를 사용한다. 연결 모드에서 기기 기록으로 조용히 대체하거나 저장 실패를 성공으로 표시하지 않는다.
- 서버 읽기·트랜잭션 제한 시간은 15초이며, 쓰기 트랜잭션의 재시도는 최대 3회다. 실패 시 기존 화면의 오류 영역을 통해 재시도를 안내한다.
- 인터넷 연결이 필요하다. 오프라인 쓰기 대기열과 자동 재전송은 구현하지 않았다.

트랜잭션 재시도·오프라인 동작은 [Firebase 공식 문서](https://firebase.google.com/docs/firestore/manage-data/transactions)를 따른다.

<br><br><br>





## 기존 기기 기록 이관

서버에 해당 계정의 문서가 없을 때만 `bap_pool_v2_<해당 UID>_` 기록으로 서버 문서를 생성한다.
트랜잭션 안에서 존재 여부를 다시 확인하므로 먼저 생성한 기기의 서버 기록을 다른 기기가 덮어쓰지 않는다.
서버 문서가 이미 있으면 서버가 기준이며 다른 기기의 오래된 로컬 기록을 자동 병합하지 않는다.
원래 기기 기록은 백업으로 보존한다. 연결 쓰기 때 같은 UID의 이관 자료를 읽지만, 서버 문서가 이미 있으면 해당 로컬 자료를 적용하거나 병합하지 않는다.
데모 기록과 소유자를 알 수 없는 과거 공용 기록은 자동 이관하지 않는다.
기분·찜 초기화는 서버 문서의 항목만 비우며 문서를 삭제하지 않는다. 오래된 기기 기록의 재이관을 방지하기 위해 클라이언트 문서 삭제는 차단한다.

<br><br><br>





## 검증

`test/firestore_preference_store_test.dart`의 9개 테스트는 FakeFirestore로 첫 이관, 새 기기 재조회,
계정 분리·중간 계정 변경, 서버 쓰기 직렬화, 장애 복구·로컬 대체 금지, 알 수 없는 스키마 보존을 확인한다.
`tools/firebase_rules/rules.test.mjs`는 실제 Firestore Emulator에서 취향 접근 제어와 두 클라이언트의 동시 트랜잭션을 검증한다.
Mock·Emulator 성공은 실제 Firebase 사용자 계정이나 실제 두 기기에서의 검증을 의미하지 않는다.

학습 모델 도입 후에는 추천 당시 조건·후보·추첨 확률·반응을 최근 30일 내 최대 64개 노출에 연결하고(반응 기록 우선 보관),
학습 가중치를 취향 변경과 같은 트랜잭션에 저장한다. [모델·수집·보관 정책](LEARNING_MODEL.md)을 참조한다.
